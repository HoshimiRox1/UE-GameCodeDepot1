# 核心要点 - 接口

> 通过接口实现功能的解耦，主角只负责调用接口，执行接口的 Actor 具体实现接口内容

因为 `BP_MainCharacter`（以下称为主角），主要是基于 C++ 的蓝图，所以本项目优先使用 **C++ Interface**，并允许蓝图实现接口函数。

这里不要把 C++ Interface 理解成“以后升级为 BPI”的前置版本：
- **C++ Interface**：适合当前项目，因为主角基于 C++，接口可以被 C++ 和蓝图共同调用。
- **BPI（Blueprint Interface）**：适合纯蓝图项目，但它不是 C++ Interface 的升级版。

因此当前路线是：**先做 C++ Interface，并通过 `BlueprintNativeEvent` / `BlueprintCallable` 暴露给蓝图实现。**

## 接口参数设计

```cpp
// 接口的内容 - 伪代码
Interact(Interactor : Actor);					// 负责 InteractableActor 执行交互逻辑
GetInteractPrompt(Interactor : Actor) -> Text;	// 返回 InteractableActor 对应的交互提示词
CanInteract(Interactor : Actor) -> bool;		// InteractableActor 自行判断交互状态，以给GetInteractPrompt根据状态显示文本
```

- Interactor 只传 Actor，交互 Actor 自己内部 `CastTo`

- `SetCurrentInteractTarget()
- `ClearCurrentInteractTarget()``

# 可交互 Actor

> 可交互 Actor 分为三类：
> - 简单查看 Actor
> - 交互获取 Actor
> - 附着移动 Actor

**每个交互 Actor 都需要具体实现接口的内容**

## 简单查看 Actor - 『最小回环』

> [!example] 梳妆台的全家福
> 交互后，物件响应接口，打开一个“查看大图 + 描述文字”的 UI，玩家关闭 UI 后回到正常控制（这个比以上两个交互都简单）

 **交互流程：**
  1. 主角进入相框的可交互范围；
  2. 玩家按下 `IA_Interact`；
  3. 主角调用当前目标的 `Interact` 接口；
  4. 相框 Actor 在接口实现中打开查看 UI；
  5. UI 显示全家福大图和描述文字；
  6. 玩家关闭 UI，恢复主角控制。

**交互发现方式**
交互用 BoxCollision，命名为 `InteractionBox`
 `InteractionBox` 只放在玩家允许交互的位置，例如全家福相框的正前方。主角进入该范围时记录当前交互目标，离开范围时清除目标。玩家按下 `IA_Interact` 后，主角只调用当前目标的接口。

### BP_InspectableActor

> 我决定将全家福相框和梳妆台做分离，因此将『全家福相框』这类简单查阅的 Actor 抽象为 `BP_InspectableActor` 以便复用

# 交互系统的最小回环

> [!example] 最小回环例子
> 实现全家福相片的交互，UI 查阅，关闭后回退到主界面

**相关 Gameplay 要素**
```text
BP_MainCharacter
职责：检测当前可交互目标，按 E 时调用接口

BP_InspectableActor
职责：保存查看数据，并实现 Interact 接口；交互发生时把标题 / 图片 / 描述交给 PlayerController

BP_PlayerController
职责：统一打开/关闭查看 UI，切换输入模式，恢复主角控制

WBP_InspectView
职责：只负责显示大图、标题、描述、关闭按钮，不决定交互业务逻辑
```

**职责边界补充**
```text
BP_InspectableActor.Interact(Interactor)
→ 读取 InspectTitle / InspectImage / InspectDescription
→ 通过 Interactor 获取 PlayerController
→ 调用 PlayerController.OpenInspectView(...)
→ PlayerController 创建 WBP_InspectView 并切换输入模式
→ WBP_InspectView 只显示传入内容
```

这样可以保持边界清晰：
- Actor 提供内容
- PlayerController 管理 UI 生命周期和输入模式
- Widget 只负责展示

*交互判断*
-  `CurrentInteractTarget` - 主角持有的变量，负责判断 InspectableActor 是谁
-  `Overlap的Begin/End` 由持有 InteractBox 的 Actor 负责，负责传递 Self 给主角
- 主角通过 `SetCurrentInteractTarget` 和 `ClearCurrentInteractTarget` 函数设置和清除交互对象

*可交互 Actor 的基本逻辑*
**BeginOverlap()** 
- 判断 Overlap 进来的是不是主角
- 主角调用 `SetCurrentInteractTarget(Self)`
- `GetInteractPrompt()` 
- `RefreshInteractPrompt`
- `ShowInteractPrompt` (要播过渡动画)

**EndOverlap()**
- 判断 Overlap 离开的是不是主角
- 只有当 `CurrentInteractTarget == Self` 时，主角才调用 `ClearCurrentInteractTarget()`
- `HideInteractPrompt`（要播过渡动画）

> 这里加 `CurrentInteractTarget == Self` 判断，是为了避免以后多个可交互范围重叠时，离开 A 物体却把 B 物体的当前目标也清掉。

**Keyboard Events F**
- 需要刷新交互状态就 `RefreshInteractPrompt`
